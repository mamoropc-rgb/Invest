# Двусторонний обмен с walletfree — протокол v1

## Источники истины

- **walletfree** — единственный владелец денежных счетов, денежных остатков и общего финансового учёта.
- **Инвестиции** — единственный владелец списка ценных бумаг, количества, сделок, ручных котировок, купонов и дивидендов.
- Входящие события **не должны дважды** увеличивать / уменьшать наличность или общие активы. Покупка — обмен денег на бумаги, а не расход в бытовой аналитике.

## Что реализовано в этом репозитории

Android `ContentProvider`:

`content://com.mamoro.investments.sync/events?after=<sequence>`

- `query()` возвращает максимум 500 событий с полями `sequence`, `event_id`, `operation_id`, `kind`, `payload_json`, `created_at`.
- `ContentResolver` получает уведомление `notifyChange` при добавлении события. Внешний клиент должен также проверять события при запуске, потому что Android может не доставить уведомление закрытому приложению.
- `call("ackEvents", null, Bundle { through_sequence: Long })` подтверждает **только уже применённые и зафиксированные** Wallet события.
- `call("publishWalletAccount", null, Bundle {...})` передаёт последнюю фотографию счёта Wallet в приложение «Инвестиции». Поля: `account_id:String`, `name:String`, `currency:"RUB"`, `balance_minor:Long`, `updated_at:Long`.
- В приложении «Инвестиции» есть очередь событий, сохраняемая через Room, и индикатор числа неподтверждённых записей.

### Виды событий

| kind | Значение |
|---|---|
| `TRADE_UPSERT` | Создание покупки/продажи. Поля `side`, `quantity_micros`, `unit_price_minor`, `fee_minor`, `cash_delta_minor`, `wallet_account_id`, `security_id`, `operation_id`, `happened_at`, `currency` |
| `TRADE_DELETE` | Удаление сделки; в Wallet нужно удалить/аннулировать денежную запись по `operation_id` |
| `INCOME_UPSERT` | Купон или дивиденд с `income_kind`, `cash_delta_minor` и идентификаторами |
| `INCOME_DELETE` | Удаление купона/дивиденда с аннулированием денежной записи |

Схема JSON включает `schema_version: 1`, `event_id`, `source_app`, `event_kind`. Денежные значения — целые копейки, количество — миллионные доли бумаги. Общая валюта v1 — `RUB`. Положительное `cash_delta_minor` означает пополнение свободных денег; отрицательное — уменьшение.

### Ключи идемпотентности

- `event_id` — уникальный ID сообщения. Повторное получение не должно повторно проводить денежную операцию.
- `operation_id` — стабильный ID денежной операции; при удалении должна аннулироваться **та же операция**.
- `sequence` — монотонный локальный порядковый номер. Wallet сохраняет свой watermark и после рестарта дочитывает новые события.
- Запись операции в Wallet и фиксация `event_id` должны быть атомарными (одна транзакция Room). Только после сохранения можно подтверждать `ackEvents`.

## Защита данных

Сейчас провайдер объявлен с разрешением уровня `signature` и дополнительно проверяет подпись вызывающего UID в `call()`. **Обе программы должны иметь одинаковый сертификат подписи**, иначе Android не даст доступ. Подпись новой программы подготовлена отдельно; существующую программу walletfree **нельзя переподписывать без проверки её текущего сертификата** — иначе обновление поверх установленной версии перестанет работать.

Если walletfree уже использует другой ключ, до внедрения обмена нужно разработать безопасный протокол привязки с отдельной аутентификацией и перенести данные. Ни в коем случае не делайте провайдер общедоступным (`exported=true` без ограничений).

## Обязательная доработка в walletfree (НЕ выполнена)

1. Проверить имя пакета, сборку, Room-схему и отпечаток сертификата walletfree.
2. Добавить в манифест walletfree:
   `<uses-permission android:name="com.mamoro.investments.permission.SYNC" />` и в `<queries>` запись `<provider android:authorities="com.mamoro.investments.sync" />`, если используется targetSdk 30+.
3. Встроить `walletfree-integration/WalletInvestmentsBridge.kt` и вызвать импорт из фонового потока при открытии приложения и после уведомлений. Сохранить watermark и idempotency IDs.
4. Для каждой сделки создавать **связанную бухгалтерскую запись** с типом «операция с инвестициями», исключённую из обычных бытовых расходов; учитывать комиссию отдельно; не удваивать рыночную стоимость актива в общем балансе.
5. Сопоставить `wallet_account_id` с брокерским субсчётом. При пустом или незнакомом ID не проводить операцию и не подтверждать её — предложить пользователю привязать счёт.
6. Передавать снимки брокерских денежных субсчетов в «Инвестиции» через `publishWalletAccount` после каждого обновления и на старте.
7. Обновлять общую стоимость инвестиций только по реальным данным из «Инвестиций» (отдельный импорт позиций/оценки будет добавлен в протокол v2), а не выводить её из движения денег.
8. Проверить сценарии: офлайн; повторные события; удаление; восстановление после прерывания; два брокерских счёта; смена подписи; изменение цен; переустановка.

**До интеграции с walletfree обмен не активирован. Приложение «Инвестиции» работает автономно; операции не меняют деньги в «Кошельке».**
